## The nine decisions, and why

CLAUDE.md flags US-6 as the highest-stakes story in Phase 1, so these were settled before
the first migration was written rather than discovered afterwards.

1. **One `User` table for every authenticated principal.** A portal customer has both a
   `User` row (credentials, locale) and a `Customer` row (the CRM record), linked by an
   optional `Customer.userId`. Password hashing, lockout, and token revocation are then
   built once in P02 instead of twice. Rejected alternative: separate credentials on
   `Customer`, which is common in helpdesks but doubles the auth surface.
2. **Permission scope lives on the role↔permission grant**, not on the permission.
   `PermissionScope` is `OWN | DEPARTMENT | BRANCH | ALL`, so `ticket.read` means one thing
   for an agent and another for a manager. This is the concrete mechanism behind the
   project rule that scoped permissions are applied *in the query*.
3. **`Attachment` hangs off `Message`, never off `Ticket` directly.** Visibility is decided
   in exactly one place, so a file on an internal note is internal by construction rather
   than by someone remembering to check. `ticketId` is carried as a denormalised shortcut.
4. **Bilingual handled two ways on purpose.** Short labels get `nameEn`/`nameAr` column
   pairs. Knowledge articles get one row per locale tied by `translationGroupId`, because
   bodies are long, are published independently, and the Arabic version often lags.
5. **SLA state is denormalised onto `Ticket`.** The SLA sweep and the agent list sorted by
   time remaining are hot paths that must hit an index on `Ticket` rather than join out on
   every read. `SlaPolicy` is one row per `(priority, department)`, `departmentId NULL`
   being the platform default.
6. **Prisma default table naming**, no `@@map`. Simpler system, one name everywhere; the
   cost is that hand-written SQL in P11 needs double quotes. Reversible as a rename
   migration until production data exists — revisit before the first deploy, not after.
7. **`uuid(7)` primary keys, plus `Ticket.number` as a sequential `Int`.** v7 is
   time-sortable so index locality holds; the number is the human reference ("#1043"),
   generated by PostgreSQL so concurrent submissions cannot collide.
8. **`TicketHistory` and `AuditLog` are separate, both append-only** — no `updatedAt`, no
   `deletedAt`. Different readers, different retention. `AuditLog.entityId` is a plain
   string with no FK because it outlives the rows it describes.
9. **Delete behaviour.** `Ticket.customer` is `Restrict`; children cascade; every optional
   reference is `SetNull`, so removing a category or department cannot take tickets with it.

## Status — 2026-08-26

**04 / US-6 — executed. Notion status `In review`.**

`npm run verify` green: typecheck, lint, format:check, and **62 tests** (11 shared, 51
backend). Migration `20260825221631_core_domain_schema` drops `MigrationProbe` and creates
**18 tables** (the 16 required plus `UserRole` and `RolePermission`), **11 enum types**,
**58 indexes**, and **36 foreign keys**.

### The one gap that needed filling

AC4 says timestamps are maintained "automatically". `createdAt`/`updatedAt` genuinely are.
**`deletedAt` is not** — Prisma has no built-in soft delete, and asking forty later stories
to remember `where: { deletedAt: null }` fails the first time someone forgets, silently, by
showing a deleted customer to an agent.

So this story adds `src/prisma/soft-delete.extension.ts`, reached as
`prisma.notDeleted.ticket.findMany()`. The unfiltered client stays available for restore,
export, and hard-delete paths — deliberately the longer-looking path, so using it is a
decision rather than an accident. Two documented limits: `findUnique` is not filtered
(Prisma only accepts unique fields in its `where`), and nested relation reads are not
filtered.

### Deviations from plan

- **`prisma.service.test.ts` and `migrations.test.ts` both had to change**, as US-5
  predicted, because they referenced the dropped `MigrationProbe`. The migration test now
  asserts the replayed history produces `Ticket`, `Message`, `Customer`, `User`, that
  `MigrationProbe` is gone, and that `Message.isInternal` exists and is `NOT NULL`.
- **The pooling test lost its "every count agrees" assertion.** Pointing it at `Ticket`
  made it race with other test files writing tickets in the same database, and agreement
  was never what that test was about. It now asserts every concurrent query resolves.

## What the next stories inherit

- **US-7** (API conventions) — the error envelope will need to map Prisma's constraint
  errors (P2002 unique, P2003 foreign key, P2025 not found) onto HTTP.
- **US-10** (Redis) — add `redis` as one more entry in the health `dependencies` map.
- **US-12** (seed data) — needs at least the system roles, permissions, and a default
  `SlaPolicy` row per priority, or the platform boots with nobody able to do anything.
- **P02** — `User.passwordHash` is a plain column with no hashing attached yet. That is
  auth's job, not the schema's.
